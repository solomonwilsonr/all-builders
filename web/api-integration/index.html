THE ESSENTIAL ENDPOINTS

Start with the listing. Follow the evidence.

Use the product ID returned by identification for product-specific requests.

POST

/v1/products/identify

Resolve a listing URL or title to a known product.

POST

/v1/listings/trust-check

Inspect pricing, seller signals and possible copies.

GET

/v1/products/{id}/safety

Read the product’s safety findings and supporting evidence.

GET

/v1/products/{id}/certifications

Look up safety-mark checks against registries.

GET

/v1/products/{id}/alternatives

Explore alternatives available in the product record.

GET

/v1/evidence?ids=…

Retrieve source records for evidence IDs returned by a check.

Check /health for mock mode and available real endpoints. X-SafeShelf-Source: mock indicates example data, not actual product findings.

WHEN A REQUEST NEEDS ATTENTION

Know what comes back.

401 · Authentication required +

If the server enables API_KEY, send its value in the X-API-Key header. Ask the server owner for access. Keep the key in server-side environment variables.

429 · Too many requests +

Respect the Retry-After response header and retry after the indicated delay.

Example results instead of live findings +

Inspect /health and X-SafeShelf-Source. A local server defaults to mock responses. Do not present those results as findings about a real product.

Browser or network errors +

Confirm the API server is running and reachable. A deployed application cannot reach your computer’s localhost. For authenticated integrations, call from your backend to keep API keys private.
